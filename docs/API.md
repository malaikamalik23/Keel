# HTTP API

The dashboard is a client of this API; anything it does, a script can do too. The full, always-current reference is
generated by FastAPI: open **http://127.0.0.1:8000/docs** while Keel runs (the raw schema is at `/openapi.json`).
This page covers how to call it and the endpoints you are most likely to want.

## Authentication

| Your setup | What a request needs |
|---|---|
| No `API_KEY` (your own laptop) | Nothing, but only from this computer, to `http://127.0.0.1:<port>` or `http://localhost:<port>`. Requests from another device, through a proxy, or that look cross-site are refused with 403. |
| `API_KEY` set (Docker, a server, another device) | The header `X-API-Key: <your key>` on every `/api/*` request. `/health` needs nothing. |

There is one key for the whole API: Keel is single-user. Endpoints that call the model (`/api/chat`,
`/api/scheduler/tick`, service checks, backups) are rate-limited per client (`RATE_LIMIT_PER_MINUTE`, default 30).

Errors come back as JSON `{"detail": "..."}` with 401 (key missing or wrong), 403 (refused origin), 404 (no such item),
409 (conflict, e.g. backups not set up), 422 (invalid input) or 429 (rate limit).

## Examples

**bash / macOS / Linux**

```bash
KEY=your-api-key   # leave out the -H line below if API_KEY isn't set
curl -s http://127.0.0.1:8000/health
curl -s -H "X-API-Key: $KEY" http://127.0.0.1:8000/api/tasks
curl -s -H "X-API-Key: $KEY" -H "Content-Type: application/json" \
     -d '{"message": "Plan my day, I have 4 hours"}' http://127.0.0.1:8000/api/chat
```

**Windows PowerShell**

```powershell
$h = @{ "X-API-Key" = "your-api-key" }   # use @{} if API_KEY isn't set
Invoke-RestMethod http://127.0.0.1:8000/api/tasks -Headers $h
Invoke-RestMethod http://127.0.0.1:8000/api/chat -Method Post -Headers $h -ContentType "application/json" `
  -Body (@{ message = "Plan my day, I have 4 hours" } | ConvertTo-Json)
```

A chat reply looks like this (shortened):

```json
{
  "conversation_id": 12,
  "reply": "Here's a 4-hour plan: ...",
  "tool_calls": [{"name": "create_daily_plan", "permission": "write", "status": "ok", "input": {"capacity_minutes": 240}, "result": {"...": "..."}}],
  "pending_action_ids": []
}
```

Pass `conversation_id` back to continue the same conversation; leave it out to start a new one. When the reply
queued something for approval, its id is in `pending_action_ids`.

**Approve or reject a queued action**

```bash
curl -s -H "X-API-Key: $KEY" http://127.0.0.1:8000/api/pending-actions          # what is waiting, with the exact summary
curl -s -X POST -H "X-API-Key: $KEY" http://127.0.0.1:8000/api/pending-actions/7/confirm
curl -s -X POST -H "X-API-Key: $KEY" http://127.0.0.1:8000/api/pending-actions/7/reject
```

Approving re-checks the target: if the item changed since the request was queued, nothing is done and the reply says
why. An action whose integration was switched off meanwhile is refused too.

## Endpoints by area

| Area | Endpoints |
|---|---|
| Chat | `POST /api/chat` · `GET /api/conversations/{id}/messages` |
| Approvals and audit | `GET /api/pending-actions` · `POST /api/pending-actions/{id}/confirm` · `POST /api/pending-actions/{id}/reject` · `GET /api/audit-log` |
| Tasks and plans | `GET /api/tasks` · `POST /api/tasks/{id}/complete` · `GET /api/tasks/{id}/events` · `GET /api/plan` · `GET /api/plan.ics` · `PATCH /api/plan-items/{id}` · `GET /api/briefing` · `GET /api/work-sessions` · `GET /api/recommendations?energy=low&minutes=30` (what to do now, with reasons) |
| Goals, projects, commitments | `GET /api/goals` · `GET /api/projects` · `GET /api/projects/{id}/report` · `POST /api/projects/{id}/entries` · `POST /api/projects/{id}/links` · `GET /api/commitments` · `PATCH /api/commitments/{id}` · `PATCH /api/goals/{id}` · `PATCH /api/milestones/{id}` |
| People | `GET /api/people` · `POST /api/people` · `GET /api/people/{id}` · `PATCH /api/people/{id}` · `DELETE /api/people/{id}` · `POST /api/people/{id}/contacts` (body `{"note": "...", "on_date": "2026-11-20"}`) · `DELETE /api/person-contacts/{id}` |
| Memory | `GET /api/memories` · `GET /api/memories/review` · `POST /api/memories` · `PATCH /api/memories/{id}` · `DELETE /api/memories/{id}` |
| Applications | `GET /api/opportunities` · `POST /api/opportunities` · `PATCH /api/opportunities/{id}` · `GET /api/opportunities/{id}/eligibility` · `GET /api/opportunities/{id}/readiness` · `DELETE /api/drafts/{id}` |
| Documents | `GET /api/documents` · `POST /api/documents/upload` · `POST /api/documents/index` · `DELETE /api/documents/{id}` · `GET /api/document-links` · `DELETE /api/document-links/{id}` |
| Calendar | `GET /api/calendar?start=2026-11-23&days=7` |
| Reminders and check-ins | `GET /api/reminders` · `POST /api/reminders/{id}/cancel` · `GET /api/checkins` · `POST /api/checkins/{id}/response` · `GET /api/notifications` · `POST /api/scheduler/tick` |
| Workflows | `GET /api/workflows` · `GET /api/workflow-templates` · `POST /api/workflows` · `PATCH /api/workflows/{id}` · `DELETE /api/workflows/{id}` · `POST /api/workflows/{id}/run` · `POST /api/workflow-runs/{id}/approve` (or `/cancel`, `/retry`) |
| Insights | `GET /api/analytics` · `GET /api/accountability` |
| Services | `GET /api/services` · `POST /api/services/{id}/test` · `PUT /api/switches/{id}` (body `{"on": false}`) |
| Backups | `GET /api/backups` · `POST /api/backups` (restoring is CLI-only) |
| Retention | `GET /api/retention` · `PUT /api/retention` (body `{"audit_log": 90}`, `null` = forever) · `POST /api/retention/preview` · `POST /api/retention/apply` |

No endpoint returns a key, token, password or the calendar's secret address. The model has no access to the
switch, retention, backup or approval endpoints: they are for you (or your scripts) only.
